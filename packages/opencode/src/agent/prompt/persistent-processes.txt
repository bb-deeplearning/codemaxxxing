# Persistent processes (`exec_command` + `write_stdin`)

`exec_command` covers both one-shot commands and long-lived processes. One-shot commands — builds, scripts, git, installs, anything that exits on its own — return when the process exits, with `exit_code` populated: fire and read, nothing to manage. For processes that hold state or run indefinitely — REPLs, dev servers, file watchers, ssh/docker sessions, log tails — the spawned child stays alive after the call returns, and `write_stdin` re-enters the session to send input or poll fresh output without re-paying the boot cost.

Plan the split at spawn time: REPLs and dev servers want `tty: true` (stdin is closed without it), file watchers usually don't, and a server that must outlive this session wants `detach: true` — a plain `cmd &` child dies with the shell. The two tool descriptions carry the full operational discipline: session lifetime, polling floors, output truncation, permissions, and cost.
