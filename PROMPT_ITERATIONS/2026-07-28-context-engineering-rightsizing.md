# Iteration 11: Context-engineering rightsizing — judgment over rules, dedup over repetition

**Date**: 2026-07-28

Iteration 10 (2026-07-24) re-baselined the prompts against Anthropic's official fable-5 prompting guides and adopted the behavioral blocks (act-when-ready, evidence-grounded claims, end-turn check, outcome-first). The same day it landed, Anthropic published the second half of the guidance: [The new rules of context engineering for Claude 5 generation models](https://claude.com/blog/the-new-rules-of-context-engineering-for-claude-5-generation-models) (tweet 2080710971228918066) — the "we removed over 80% of Claude Code's system prompt" piece. Iteration 10 absorbed the field guide's model-side behaviors; it did not absorb the context-side lessons: rules-over-judgment, examples-over-interfaces, and saying everything two or three times. This iteration is the corresponding deletion pass, done in the same documented manner, touching every claude-family and shared prompt surface.

## Discovery

Audit of the assembled root-session context (system prompt + capability fragments + tool descriptions + global AGENTS.md), collected 2026-07-28:

1. **Rules where judgment should be — one directly fighting the intended workflow.** `session/prompt/anthropic.txt:11` carried "NEVER create files unless absolutely necessary... This includes markdown files" (duplicated at `general/anthropic.txt:22`) — near-verbatim the class of rule Anthropic reports deleting, and in direct conflict with the artifact-driven fable workflow the [field guide](https://claude.com/blog/a-field-guide-to-claude-fable-finding-your-unknowns) teaches (implementation-notes.md, HTML prototypes, plan artifacts, explainers). Every artifact request forced the model to reason past a NEVER in its own system prompt — the article's "conflicting messages" failure mode, reproduced locally. Same class: the comment rule-list (`anthropic.txt:67`), the TodoWrite section with caps-lock scolding plus an 18-line worked example (`anthropic.txt:36-60`), and explore.txt's seven-line "=== CRITICAL: READ-ONLY ===" prohibition list for operations its toolset already denies mechanically.
2. **Triple-stated prose.** The escalation-ratchet sentence existed near-verbatim in THREE places in one assembled context (`anthropic.txt:86`, `multi-agent-root.txt:117`, `~/.config/opencode/AGENTS.md:20`). Delegation restraint existed in three (`anthropic.txt:85`, `multi-agent-root.txt`, and the `agent-spawn.txt` tool description — the latter two sharing section names AND bullets verbatim: When to delegate / When NOT / Scoping / After you delegate / Cost / Limits). `persistent-processes.txt` (34 lines, always-on) was a near-total duplicate of the `exec_command`/`write_stdin` tool descriptions: tty rule, session lifetime, poll floor, 64-cap, head/tail truncation, detach, cost model — all stated twice per session.
3. **Phantom bash — Discovery #2 of iteration 10, second specimen.** `registry.test.ts:204` pins that the model-visible tool list has NOT contained "bash" since Wave 4 (replace-bash-task, May 2026; "bash" survives only as exec_command's permission key). Yet `persistent-processes.txt` taught a bash-vs-exec_command *choice*, `anthropic.txt:92` said "Reserve Bash for actual system commands", and `explore.txt:24` taught "Use Bash ONLY for read-only commands: ls, find, wc, git status/log/diff/show/blame" — doubly phantom, since explore denies `exec_command` entirely (pinned in `system-prompt-regression.test.ts:127`) and therefore has no shell at all. The default/codex/kimi/gemini/trinity session prompts carried the same dead references. Two months of every session being taught at least one tool it could not call.
4. **Progressive-disclosure miss in the per-machine config.** The agent-browser discipline block (9 dense lines of daemon/orphan scar tissue) loaded into EVERY session on bbtws via the global AGENTS.md, browser work or not — while an agent-browser skill already exists and loads exactly when browser work starts.
5. **What was already right (and stayed):** the iteration-10 behavior blocks are the officially recommended fable prose; the subagent delivery contract + ABORT protocol is the standing fix for the iteration-10 silent-delivery failure (`ses_076dbcccbf`) and matches the article's "avoid overconstraining, *except in highly important areas*" carve-out; the permission-gated fragment machinery IS progressive disclosure — right mechanism, wrong payload sizes.

## Research

- **The context-engineering article** (claude.com, 2026-07-24): >80% of Claude Code's system prompt removed for Opus 5 / Fable 5 with "no measurable loss on our coding evaluations." The then/now myths: give-rules → let-judgment (their deleted example includes "Don't create planning, decision, or analysis documents unless the user asks for them"; their comment rules collapsed to "Write code that reads like the surrounding code: match its comment density, naming, and idiom"); give-examples → design-interfaces (examples constrain the exploration space; the TodoWrite status enum IS the guidance); put-it-all-upfront → progressive disclosure (verification/code review moved into skills; deferred-loading tools); repeat-yourself → tool descriptions own tool mechanics, stated once; CLAUDE.md guidance: lightweight, gotchas-heavy, never state what the file system already shows.
- **The field guide** (claude.com, 2026-07-06, tweet 2073100352921215386): map-vs-territory, the four unknowns quadrants, over-specific prompts followed off a cliff vs over-vague prompts filled with industry defaults. Iteration 10 already adopted its behavior blocks; the residual adoption here is one prompt-side posture — surface unknowns that would change the shape of the work instead of silently guessing.
- **Claude Code v2.1.220 ground truth** (Piebald extraction current at 2026-07-24; assembled Fable-5 prompt fetched from the asgeirtj mirror): what survived their cut is identity + a 5-bullet Harness + the communication contract + the autonomy block + memory/scratchpad *interfaces*. There is NO TodoWrite section, NO over-engineering rule list, NO URL rule, NO file-creation ban — the ban's replacement is a scratchpad *directory* (an interface giving working files a home, not a rule forbidding them). Delegation guidance lives inside the Agent tool description ("When to use"), not the prompt body. Comments are exactly two judgment lines.
- **Cut-depth calibration**: CC's 80% came off a much fatter base plus mass-relocation into tools and skills. This fork already took the iteration-10 slimming, so the same *shape* lands at ~45% on the claude-family prompt files and ~50-85% on the fragments whose content the tool descriptions already carry. Matching the shape, not the percentage, is the point.

## Observe

- **The artifact unlock is the behavior change to watch.** Models should now produce working notes/prototypes/plans when useful without being asked twice — that is intended. Watch for the failure inversion: repo litter. The "keep them off the shipped surface, clean up strays" clause should hold it; if strays appear in commits, tighten that one line, not the ban.
- **TodoWrite usage without the scolding section.** The tool description carries when-to-use. If long multi-step tasks start dropping todo tracking (user-visible progress loss), restore ONE calm sentence in the prompt — not the example.
- **Delegation quality with restraint prose now only in tool descriptions.** Iteration 10's restraint tests moved from prompt to `agent-spawn.txt` ownership. Watch for fable over-delegating trivia again; if it does, the fix belongs in the tool description, stated once.
- **Delivery compliance must not move.** The contract was kept verbatim; the fleet baseline is 43/45 compliant with the residual pocket in 80+-message review sessions. If `safety_net_firing_rate` re-appears in a slimmed-fragment world, the cut went too deep in the subagent fragment — the delivery contract is the last section to ever shrink.
- **Context-size receipt**: the six claude-family/shared surfaces went 492 → 285 lines (-42%); the three always-on capability fragments went 246 → 129 (-48%). Every deleted line was either stated elsewhere in the same assembled context or taught a tool that does not exist.
- Prose pins stay the tripwire for the next rewrite: the trims were drafted against the pin list up front (headers, doctrine tokens, section order), and the suites passed on the first post-rewrite run — the pins are doing exactly the job they were built for.
